    MeshService

    A service in the mesh, selecting its proxies and declaring its ports and identities.

    Kuma

    Behaviour per target

    --to-latest v2 (2.x) rewritten

    Output: MeshService

    • spec.ports[].protocol → appProtocol (auto-fixed).
    • spec.selector.dataplaneTags is reported: 3.0 drops it silently and the service matches no proxies. Not rewritten on v2: on 2.14 a labels selector also matches same-named services synced from other zones.
    • Names that are not RFC 1035 labels are reported.
    --to-latest v3 (3.0) rewritten

    Output: MeshService

    • ports[].protocol → appProtocol.
    • selector.dataplaneTags → selector.dataplaneLabels.matchLabels. The keys must exist as labels on the Dataplanes (Pod labels on Kubernetes, top-level labels on Universal).
    • identities[] entries of type: ServiceTag removed; add type: SpiffeID entries if clients need them.
    • Control-plane-owned labels removed.

    Timeline

    VersionChange
    2.8ports[].protocol renamed to appProtocol.
    2.10Names that are not RFC 1035 labels deprecated.
    3.0dataplaneTags removed; identities accepts SPIFFE IDs only; non-RFC 1035 names rejected.
